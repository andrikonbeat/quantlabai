# Design: Guardian Control Loop

## Technical Approach

Two independent slices shipped in order. **Slice A (structural):** fail closed on missing guardian providers, enforce `PortfolioState` gates after `GuardianEvaluationStage`, and serialize typed `RiskConfig` into CFX `risk_money_mgmt`. **Slice B (adaptive):** introduce a unidirectional `CorrectionBus` between guardian and builder, adaptive `CustomProject` template selection, and guardian metrics persistence with a read API.

Both slices reuse existing stage contracts and CFX infrastructure; no new subprocesses or routing boundaries are introduced.

---

## Architecture Decisions

| Option | Tradeoff | Decision |
|--------|----------|----------|
| Provider injection via constructor vs pipeline_config dict | Constructor is stricter; config dict is backward-compatible | Constructor injection on `MetaGuardianOrchestrator`; `GuardianEvaluationAgentStage` reads providers from `pipeline_config` and passes them through. |
| CorrectionBus as asyncio.Queue vs callback list | Queue adds decoupling and back-pressure; callbacks are simpler | asyncio.Queue fan-out (1 publisher, N subscribers). One pipeline tick delivery guarantee. |
| RiskConfig mapping via raw XML strings vs typed sub-model | Raw XML matches existing `SettingsSection` pattern; typed sub-model adds validation cost | Raw XML strings generated by a `RiskConfigMapper`, validated before write. |
| Guardian feedback in JSONL vs SQLite extension | JSONL matches `metrics.jsonl` spec and is append-safe; SQLite requires migration | JSONL append-only in `GuardianFeedbackStore`; `TimeSeriesStore` gains a guardian-facing read API. |
| TemplateSelector as static rules vs ML-based selection | Rules are deterministic and auditable; ML adds unpredictability | Static rule table keyed by `PortfolioState`; deterministic by design. |

---

## Data Flow

```
GuardianEvaluationAgentStage.execute()
    │
    ├── builds concrete guardians (no _NullDataProvider)
    ├── MetaGuardianOrchestrator.evaluate()
    │       ├── _collect_guardian_results()
    │       ├── _determine_state() → PortfolioState
    │       └── CorrectionBus.publish(CorrectionEvent)
    │
    └── writes guardian_state + portfolio_state to ctx.artifacts

BuilderStage.execute()
    │
    ├── reads portfolio_state, correction_events
    ├── if QUARANTINE/DEFENSIVE → raise PortfolioStateBlockedError
    │       └── waits for HUMAN_APPROVE_DEPLOY
    ├── RiskConfigMapper.to_cfx(risk_config) → BuildTask.risk_money_mgmt
    └── CfxWriter.write() → CFX archive
```

## Interfaces / Contracts

```python
# sdk/quantlab/guardian/correction_bus.py
class CorrectionEvent:
    event_id: UUID
    timestamp: datetime
    source: str
    event_type: Literal["risk_delta", "state_transition", "capital_adjustment"]
    payload: dict[str, Any]
    correlation_id: str | None

class CorrectionBus:
    def publish(self, event: CorrectionEvent) -> None
    def subscribe(self, handler: Callable[[CorrectionEvent], None]) -> Callable[[], None]

# sdk/quantlab/cfx/risk_mapper.py
class RiskConfigMapper:
    def to_cfx(self, config: RiskConfig) -> SettingsSection
    def from_cfx(self, section: SettingsSection) -> RiskConfig

# sdk/quantlab/knowledge/guardian_store.py
class GuardianMetricRecord(BaseModel):
    record_id: UUID
    campaign_id: str
    timestamp: datetime
    guardian_name: str
    score: float | None
    portfolio_state: PortfolioState
    risk_metrics: dict[str, Any] | None
    correlation_id: str | None
    source: Literal["evaluation", "live_stream", "manual"]

class GuardianFeedbackStore:
    def write(self, record: GuardianMetricRecord) -> None
    def query(self, campaign_id: str) -> list[GuardianMetricRecord]
```

## Threat Matrix

N/A — no routing, shell, subprocess, VCS/PR automation, executable-file classification, or process-integration boundary introduced by this change. All execution remains inside the existing Python pipeline and CFX archive paths.

---

## Migration / Rollout

**Slice A (structural):**
- Migrate: Update `GuardianEvaluationAgentStage` to pass concrete providers from `pipeline_config`; delete `_NullDataProvider` class.
- Rollback: Restore `_NullDataProvider` fallback and provider-optional constructor.

**Slice B (adaptive):**
- Migrate: Enable `CorrectionBus` after `GuardianEvaluationStage`; enable `TemplateSelector` before CFX serialization; initialize `guardian-feedback/` directory.
- Rollback: Disable `CorrectionBus` subscription; disable `TemplateSelector`; no schema migration needed (JSONL append-only).

Each slice ships as an independent revertible unit. Slice B depends on Slice A.
