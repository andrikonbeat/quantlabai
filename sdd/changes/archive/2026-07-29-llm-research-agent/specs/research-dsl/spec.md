# Delta for research-dsl

## ADDED Requirements

### Requirement: LLMConfig Model

The system MUST define `LLMConfig(provider: str, model: str, api_key_env: str, temperature: float, max_tokens: int, web_sources: list[str])` as a Pydantic model.

#### Scenario: Valid LLMConfig parses

- GIVEN a valid LLMConfig with provider="openai", model="gpt-4"
- WHEN the model is instantiated
- THEN all fields are set correctly
- AND temperature defaults to 0.7

#### Scenario: Invalid provider rejected

- GIVEN LLMConfig with provider="unknown_vendor"
- WHEN validation runs
- THEN a ValidationError is raised

### Requirement: Extended HypothesisConfig

The system MUST extend `HypothesisConfig` with `llm_rationale: str | None`, `source_urls: list[str]`, and `data_sources: list[str]`.

#### Scenario: Full audit fields populated

- GIVEN a hypothesis generated by LLMResearchAgent
- WHEN HypothesisConfig is inspected
- THEN source_urls and data_sources contain provider URLs
- AND llm_rationale contains the LLM reasoning

#### Scenario: Classic agent produces null rationale

- GIVEN a hypothesis from classic ResearchAgent
- WHEN HypothesisConfig is inspected
- THEN llm_rationale is None
- AND source_urls is empty

## MODIFIED Requirements

### Requirement: DSL Parsing

The system MUST parse a valid YAML research definition into a structured Pydantic model. The DSL MUST support markets, timeframes, strategy building blocks, acceptance criteria, an optional `costs` section, and an optional `llm` section with LLMConfig parameters.
(Previously: no llm config section)

#### Scenario: LLM config section parses

- GIVEN a YAML file with an `llm:` section specifying provider and model
- WHEN parsed
- THEN the research model includes an LLMConfig with those values

#### Scenario: LLM config is optional

- GIVEN a YAML file without an `llm:` section
- WHEN parsed
- THEN the research model has llm_config=None
